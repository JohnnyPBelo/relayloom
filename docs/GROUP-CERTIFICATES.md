# Group certificate foundation — verified library scope

The Node library `packages/groups/src/certificates.ts` and Go package `native/groups` implement the certificate portion of `GROUP-EPOCHS.md` with existing canonical JSON/identity proofs and maintained Ed25519 implementations. This does not yet integrate dynamic groups into application storage, synchronization, message admission or UI. The existing application still has fixed groups.

Implemented library behavior: permanent creator-signed anchors; exact-schema epoch headers and hash-linked transitions; signed invitations, fresh parent/card-bound consent and leave requests; salted private snapshots; sorted unique full-card commitments; additions versus restrictive removal/rekey paths; creator reading-card replacement without transferring signing authority; terminal closure and finite member/epoch/byte bounds. A valid header/link does not establish a globally latest head or absence of forks. The protected registry and local-left/fork fences remain separate work.

The Node foundation passed11 real cryptographic cases and the full93-test local Node gate. The Go package passed8 tests with the race detector; its separate environment-driven interop fixture is skipped in ordinary unit runs and executed by the Node vector driver. The final recorded Go command was `node scripts/go.mjs test -race -count=1 -p=2 ./groups` (5.115s). `npm run typecheck` passed. `node --import tsx --test tests/native/group-certificates.test.ts` passed one bidirectional vector case in2.227s overall, using a real Go test process and Node cryptography.

The vector driver generates fresh synthetic identities privately in the project cache, sends actual Node signatures/snapshots/ciphertext to Go, and verifies Go signatures, transitions and ciphertext in Node. It checks exact lone-surrogate/Unicode canonical bytes; invitation/consent/leave parent binding; creator authority; removal and original-reader/newcomer decryption controls; closure and snapshot commitments. Invalid creator controls are first verified as genuine signatures under the unauthorized signer's key, avoiding a merely broken-signature negative control. Private fixture files are removed after the owned process exits; only sanitized outcomes/source hashes are evidence. No owner keys or controls are used.

`docs/evidence/group-certificates/interoperability.json` records the actual result and source digest. This is cryptographic/process interoperability evidence, not group networking, a mobile-device test, or execution of all33 symbolic cases in `tests/fixtures/group-epochs.json`. The application gate must later exercise durable authority/fork/leave state, proof synchronization, partition ordering, quarantine, historical events, outbox supersession and accessible real UI before dynamic-group support is claimed.
